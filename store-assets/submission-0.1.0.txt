--- Single purpose description (max 1000 chars; this is 908) -----------

Console Hopper Creds adds a Keys button to each role on the AWS Identity Federation sign-in page (https://signin.aws.amazon.com/saml and its regional hosts) and a Keys for all roles button for the whole list. When the user clicks one, the extension exchanges the page's own SAML response for temporary credentials by calling AWS Security Token Service (AssumeRoleWithSAML) for the chosen role or roles, and shows the result in a dialog on that page in the forms a developer pastes into a terminal or a config file: environment variables for four shells, a credentials-file profile, the individual values, further snippet formats and the user's own templates. The credentials exist only while the dialog is open; nothing is stored, logged or sent anywhere but AWS. Settings cover session length, profile-name pattern, region and templates. It does one thing: turn a SAML sign-in into command-line credentials.


--- Permission justification: storage (max 1000 chars; this is 426) ----

Persists the user's settings in chrome.storage.sync: the session length to ask AWS for, the profile-name pattern, the region written into environment variables and profiles, the shell and output format last chosen, and the user's own output templates. Never credentials, never the SAML response. chrome.storage.managed is read for one key, enabled, so an administrator can switch the extension off by Chrome enterprise policy.


(The dashboard asks for a host permission justification because of the
content script's match patterns; there is no other host permission.)

--- Host permission justification (max 1000 chars; this is 847) --------

The content script runs only on https://signin.aws.amazon.com/saml and https://*.signin.aws.amazon.com/saml, AWS's SAML role picker. There it reads the page's own SAMLResponse form field to list the roles the identity provider granted, places a Keys button beside each role and a Keys for all roles button, and shows the credentials dialog when the user clicks one. No other page is touched and page content is never transmitted anywhere but to AWS: when the user clicks Keys, the SAML response and the chosen role ARN go to AWS Security Token Service (sts.<region>.amazonaws.com, or the GovCloud / China equivalent) in an AssumeRoleWithSAML request made by the service worker. That endpoint permits any origin, so no host permission for it is declared. The extension makes no other network requests, and none to servers controlled by its authors.
